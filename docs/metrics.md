# KeyPulse 统计口径与数据格式

## 1. 采集范围

| 项 | 是否采集 | 说明 |
|---|---|---|
| 按键次数 | 是 | `WM_KEYDOWN` / `WM_SYSKEYDOWN` |
| 鼠标点击 | 是 | 左 / 右 / 中 / X1 / X2 的 `BUTTONDOWN` |
| 滚轮格数 | 是 | `WM_MOUSEWHEEL` / `WM_MOUSEHWHEEL`，每次事件计 1 格 |
| 鼠标移动 | **否** | `WM_MOUSEMOVE` 频率最高，在钩子入口直接过滤 |
| 按键序列 / 字符文本 | **否** | 只存计数，不存可还原输入内容的时序数据 |
| 窗口标题 / 进程名 / 剪贴板 / 截图 | **否** | 不采集 |
| 网络行为 | **无** | 零联网、零遥测、零上传 |

## 2. 计数口径

- **按键次数**：一次 `keydown` 计 1；长按产生的 auto-repeat 由内存按下位图过滤（已置位的键不再计数）；`keyup` 只清位不计数。修饰键与组合键各自独立计数，不做组合去重。左右 `Shift/Ctrl/Alt/Win` 按不同 VK 码分开统计。
- **鼠标点击**：一次 `BUTTONDOWN` 计 1，双击计 2。滚轮不计入点击，单列统计。
- **每天**：本地自然日 `00:00:00–23:59:59`，按 flush 时刻归属。跨零点时新建当天文件，内存清零但保留按下位图。
- **小时分布**：flush goroutine 每秒把这一秒的增量结算到当前小时，精度到秒。
- **活跃分钟**：分钟位图中被置位的分钟数；只要该分钟内有任一按键或点击事件即置位。

## 3. 已知口径偏差

- 以更高完整性级别运行的进程（UIPI）产生的输入收不到，统计为近似值。
- 输入法组合过程中的部分系统按键可能被计入，与"实际打字数"不是一回事。
- 被注入的合成输入（`SendInput`）也会被计入。
- 崩溃或强杀最多丢失最近一次 flush 之后的增量（默认 1 秒，空闲时更长但空闲意味着没有数据可丢）。

## 4. 数据文件格式

一天一个 `YYYYMMDD.bin`，固定 1536 字节，纯小端：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | magic `KP01` |
| 4 | 4 | day（本地零点 Unix 秒 / 86400） |
| 8 | 4 | version = 1 |
| 12 | 20 | 保留 |
| 32 | 1024 | `[256]uint32` 各 VK 累计次数 |
| 1056 | 32 | `[8]uint32` 鼠标累计（左/右/中/X1/X2/滚轮/合计/预留） |
| 1088 | 192 | `[48]uint32` 24 小时 × (按键, 点击) |
| 1280 | 180 | 分钟活跃位图 1440 bit |
| 1460 | 76 | 保留 |

一天 1.5 KB，保留 90 天约 135 KB。`export.csv` 可导出全部历史。

## 5. 无感运行的设计约束

1. **钩子回调零分配**：只做 `atomic.AddUint32`（计数）+ `atomic.OrUint64`（脏位图）+ `atomic.StoreUint32`（心跳存活标志），不调用 `time.Now`、不发 channel、不碰文件。存活标志用 Store 而非 Add，鼠标移动每秒上千次时也不会形成 RMW 争用热点。
2. **`WM_MOUSEMOVE` 直接落空**：switch 未命中即返回，不进入任何计数逻辑。
3. **必须调用 `CallNextHookEx`**：所有分支都调用，否则用户输入会被吞掉。
4. **脏槽增量写盘**：flush 时只把变化的 4 字节槽 `WriteAt` 回原位置，连续脏槽合并成一次写；空闲 30 秒后完全停止磁盘 IO。
5. **进程优先级 `BELOW_NORMAL`**：不影响钩子回调（回调在产生输入的线程上下文执行）。
6. **耗时操作异步化**：报告生成、CSV 导出去 goroutine，不阻塞消息循环。
7. **零外部依赖**：不引 SQLite / WebView / GUI 库，`CGO_ENABLED=0`，单文件 exe。
8. **报告刷新与空闲 IO 解耦**：点开报告只续 10 分钟保活窗口；窗口内有新数据时每 ≥30 秒后台重写一次快照，页面每 60 秒自动刷新；窗口过期或采集暂停后立即停止重写，空闲仍是零额外磁盘 IO。渲染先在内存完成再一次 `os.WriteFile`，避免浏览器读到半个 HTML。
9. **历史回看不增加常驻开销**：全部历史聚合数据一次性内嵌进单文件 HTML（约 1.1 KB/天，90 天约 120 KB，上限 366 天约 400 KB）。切换单日 / 周报 / 总览由页面内 JS 完成，不重新读盘、不联网、不起服务、不增加常驻内存。**代价**是保活窗口内每次重写从约 12 KB 涨到约 120 KB，10 分钟最多 20 次 ≈ 2.4 MB 顺序写，SSD 无感；空闲时依然完全不写盘。这是用一次性的小体积写入换取任意历史切片的零延迟，比常驻 WebView 或本地 HTTP 服务便宜得多。
10. **心跳不占钩子线程**：每 2 秒只投一条 `WM_APP` 消息，检查与重挂在消息循环内完成；通知（写日志 / 托盘气泡）一律丢到独立 goroutine，绝不让文件 IO 阻塞消息循环——那会反过来诱发下一次钩子超时。空闲时心跳仍只有 1 次 `GetLastInputInfo` + 1 次 `PostThreadMessage`，无任何磁盘 IO。
11. **睡眠/休眠不依赖电源广播**：主循环比较两次 tick 的**墙上时间**（不用 `time.Since`——Go 的 monotonic 时钟在系统睡眠或虚拟机暂停期间可能同样停走），跳跃绝对值 >60 秒即判定发生了挂起，立即 `Flush(true)` 结算到当前自然日并额外触发一次钩子心跳。覆盖 S3/S4/休眠/VM 暂停/系统时间调整，零 Win32 依赖；跨零点归属仍由 `Store.Flush` 的 `stamp != 今天` 分支处理。手动大改系统时间会触发一次无害的强制结算。
12. **实时模式是唯一的可选例外**（默认关闭、重启不恢复）：托盘勾选后，主循环在每秒 `Flush` 之后、且仅当计数变化时，把当天聚合快照写成一个 1–3 KB 的 `live.js`；报告页用动态 `<script src="live.js?t=...">` 每秒读取，替换今日数据后复用 `renderDay` 局部重渲染，不整页重载。`file://` 下 XHR / fetch 会被浏览器拦截，故用经典 script 标签加载同目录脚本；不监听端口、不起服务、不联网。每帧都读**已落盘**的 `.bin`，与重新生成报告逐字段同源，避免实时数字在崩溃后倒退；钩子回调不变、仍只做原子操作；无输入时仍零额外 IO。周报 / 总览是预聚合数据，沿用原有 10 分钟保活 + 60 秒刷新，不走实时通道。

## 6. 隐私边界

本工具**不做完整键盘记录器**。默认只落盘聚合计数，不落盘原始事件序列。报告里内嵌的历史数据集同样只有「每日各 VK 计数 + 24 小时分布 + 总量」，不含时间戳序列、字符文本或窗口信息，因此扩大历史回看范围不会改变隐私等级。若未来需要原始事件流，必须满足：显式手动开启、独立加密文件、7 天自动销毁、UI 红字提示"会记录完整输入"、默认关闭，并单独评估合规风险。

## 7. 托盘图标与「今日速写」规则

**托盘图标**：运行时用 GDI 绘制 32bpp DIB + `CreateIconIndirect` 生成 HICON，无 .ico 文件、无资源编译器。尺寸取 `GetSystemMetrics(SM_CXSMICON)`（100% DPI 通常 16，高 DPI 可能 20/24/48），按**系统实际尺寸**绘制，不让 shell 把 32×32 硬缩下来；基准坐标以 32 为分母按比例映射，`size=32` 时像素与初版完全一致，`size<24` 时键帽由 3 列减为 2 列给状态点留位置。设计元素：圆角底 + 键帽 + 3 根递增统计柱 + 右上状态点。采集中为蓝底 / 白键帽 / 绿点，暂停为灰底 / 浅灰键帽 / 琥珀点；切换暂停时重建图标并 `NIM_MODIFY`，旧 HICON 立即 `DestroyIcon` 释放。GDI 失败时退回系统默认图标。单色 mask 缓冲按 `((size+31)/32)*4*size` 动态分配，不按 32 硬编码。

**今日速写**（`internal/report/summary.go`）：所有文案由当天数据触发，不写死固定句子。

- **等效对照**：按 1 次按键 ≈ 1 字符粗估，用对数距离选最接近的参照作品（《小王子》约 2 万 /《老人与海》约 6 万 /《围城》约 25 万 /《红楼梦》约 80 万字），输出"敲出了 X 的 N%"或"够写 N 部 X"。字数只是量级对照，报告里明确标注不是实际产出字数。
- **峰值时段**：3 小时环形滑动窗口，取按键 + 点击总量最大的窗口，输出起止时间与占全天比例。
- **称号**：`时段`（早鸟 / 午前冲刺 / 下午档 / 夜猫子 / 凌晨档）× `强度`（敬业 / 硬核 / 活跃 / 轻量，由按键总量与活跃分钟数决定），例如「敬业的下午档」。
- **观察条目**：按 Backspace / Ctrl / Space / Enter 占比触发输入习惯判断，另给键鼠比、与昨日对比、深夜占比、滚轮格数等条目。
- **集中度描述**：峰值窗口占比 ≥55% / ≥40% / ≥25% / 其余四档。
- **历史日对比**：速写里的"比昨天"只在存在自然前一天数据时使用；若中间有空白日，改称"比上一个记录日（YYYY-MM-DD）"，避免把非相邻日说成昨天。

## 8. 历史回看与周对比口径

- **自然周**：周一 00:00 至周日 23:59（ISO 8601）。页面最多承载 60 个周报、53 周日历热力。
- **周聚合**：7 天逐项求和；磁盘上没有 `.bin` 的日期按 0 计入；**日均固定除以 7**，不因缺记录虚高；另单列「有记录天数」（该日总量 > 0）。
- **同期对比（重要）**：含最新数据的一周若尚未到周日，其总量天然小于已结束的上一周。此时主结论改用**同期口径**——只比较双方都已过去的前 N 天（如周一–周五），变化贡献最大的一天也只在同期范围内找；双色柱里未到的日期画虚线柱。表格仍保留完整 7 天总量供参考，并在页面明确提示口径。完整周恢复总量口径。
- **环比**：`(本周 - 上周) / 上周 × 100` 取整；上周为 0 时显示「上周无数据」，不输出无穷大。
- **日历热力**：按自然周列排布，颜色按当日按键量相对全期最大值分 5 档；无数据日期为浅灰且不响应点击。
- **全期趋势**：≤60 天按天，>60 天按自然周聚合，避免上百根细柱。
- **报告数据上限**：366 天。`export.csv` 不受此限制，包含磁盘上全部历史。
- **状态保持**：当前视图记录在 `location.hash`（`#today` / `#day=YYYYMMDD` / `#week=YYYYMMDD` / `#all`），60 秒自动刷新后仍停留在原视图。

## 9. 钩子存活检测与自动重挂（P0）

低层钩子回调超过 `LowLevelHooksTimeout` 后，Windows 会**静默卸载钩子**：没有错误、没有通知，进程仍在、托盘仍在，但输入数据全部丢失。因此必须有主动探测。

**判据**：只看"计数有没有涨"无法区分掉线和用户离开。改用只读的 `GetLastInputInfo` 取系统最后一次输入事件的 tick 作为外部真值：

| 系统输入 tick | 本周期钩子回调 | 结论 |
|---|---|---|
| 未变 | 无 | 用户没操作，不动作 |
| 变化 | 有 | 健康，退避复位 |
| 变化 | **零** | 疑似掉线 → 重挂 |
| 任意 | 任意（且 `broken=true`） | 无条件重试 |

只比较 tick 是否变化、不做差值，因此不受 GetTickCount 49.7 天回绕与睡眠唤醒影响。存活标志在**所有**回调（含被过滤的 `WM_MOUSEMOVE`）入口无条件置位，否则"只移动鼠标"会被误判成掉线。首个心跳周期只建立基线，避免启动瞬间误判。

**线程约束**：低层全局钩子的回调被投递到**安装它的线程**的消息队列。因此 `Heartbeat()` 只做 `PostThreadMessageW`，真正的 `checkHealth` / `reinstall` 在 `Run()` 收到 `WM_APP+100` 后于同一锁定 OS 线程执行。换线程重装会导致新钩子永远收不到回调。

**失败与退避**：重挂先摘旧句柄，再依次装键盘/鼠标；任一失败即回滚到"无钩子"状态并置 `broken`，下个心跳无条件重试（不等输入、不过冷却），否则用户敲完一下就停会造成永久丢失。连续触发时冷却从 5 秒翻倍到最多 60 秒；任一周期确认钩子有回调即复位。锁屏、UAC 安全桌面、高完整性进程窗口都会产生"有输入但收不到回调"的假阳性，退避用来抑制这类风暴——重挂本身幂等且微秒级，不会丢数据。

**可观测性**：每次成功恢复写一行 `health.log`（`YYYY-MM-DD HH:MM:SS RECOVER gap=Ns total=N reason=input_without_callback`），只含时间、估算缺口与累计次数，**不含任何按键内容**。报告读取日志尾部（上限 64 KB，只信结构合法的行）后在顶部显示提示，明确写出"缺口内的输入未被计入，该时段统计为近似值"。托盘气泡为静默 `NIIF_NOSOUND`，5 分钟内最多一次；文案列出全部可能原因，不把假阳性说成"钩子被卸载"。

**检测延迟**：心跳周期 2 秒，正常掉线后 ≤2 秒恢复；那次触发检测的输入事件本身已丢失，故报告标注为近似值而非精确统计。睡眠/休眠唤醒时主循环会额外投一次心跳（见第 5 节第 11 条），因为唤醒是钩子最容易失效的时刻。

## 10. 版本与可追溯性

`VERSION` 文件是版本号唯一来源，`build.sh` 用 `-ldflags -X keypulse/internal/version.Version / .BuildTime` 注入。`--version` 输出版本、UTC 构建时间、目标平台与 Go 版本；同一份字符串写入报告数据集的 `ver` 字段并显示在页脚，托盘提示显示 `KeyPulse v<版本> · 采集中/已暂停`。用户提交问题时可直接附上 `--version` 与报告页脚，定位到具体构建。
